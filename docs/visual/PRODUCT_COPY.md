# Product copy and public progress

The game surfaces use brief action labels, confirmed mechanical results and
actual saved state. Runtime/model details remain at their configuration or
diagnostic decision point. RU/EN catalog keys and API/event/storage contracts
are preserved.

Campaign cards no longer present a storage revision as a chapter or show a raw
ruleset ID. The library API supplies a bounded public current-location projection:
an authored location key, or the current scene title. Authored keys use the
existing adventure locale catalog. Unknown saved locations are retained and
omitted from the card, with a safe diagnostic code; no replacement scene is
invented. Library reads do not advance the revision or save timestamp.

The saved timestamp comes from the canonical campaign response. The opened
timestamp records successful navigation on this device, after the acknowledged
campaign restoration. It is a separate, bounded 50-entry preference and is not
inferred from the server revision or advertised as other players' activity.
Stale/failed activations do not record a visit; history survives reloads.

The footer identifies configuration state and enabled preferences. A configured
provider is not advertised as a successful model connection. Model IDs, provider
plumbing and preset pipeline names are available in Settings rather than the
ordinary footer. Runtime badges show localized process states without ports or
raw error strings. Installed model files are described as found/downloaded,
not as proven inference readiness. Fixed VRAM promises and universal offline/
best-quality claims were removed.

Action cards show localized names, completion/error state and allowlisted
mechanical numbers. Dice use the engine's total; damage/healing use its new HP.
Unknown shapes remain generic and never render arbitrary provider text as
narration. Raw args/results and tool rounds remain in the existing inspector,
opened explicitly through the shell controller. A completed result with an
error is not displayed as pending. Images need no repeated source/update caption;
an unavailable owned image offers a scoped retry.

Model reasoning is not rendered in ordinary player chat. The existing application
private-context gate remains authoritative for transport publication; removing
a view is not a claim that every legacy endpoint drops every reasoning event.
Server semantic/privacy acceptance remains a separate gate in the active plan.

Validation covers the real production root in RU/EN, readonly SQLite location
projection, stale activation, local-history reload, preserved mechanical values,
hidden raw payloads, explicit inspector opening, runtime failure labels and the
affected model configuration controls. Browser fixtures prove UI contracts,
not successful inference by the installed model. Native entry/configuration
flows are rechecked at the next grouped checkpoint.

Grouped native checkpoint for Tasks 12-15 passed on the fresh isolated debug QA
build: initial entry, scoped hero/full-wizard cancel, confirmed initialized world,
settings status/advanced controls and actual SQLite cold restoration. Native
portrait decoding was checked separately before accepting the art screenshot.
Model/media inference and physical LAN acceptance remain separate.
