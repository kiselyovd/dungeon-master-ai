# Stabilize long Tauri gameplay sessions

**Date:** 2026-08-13 03:21
**Files:** `crates/app-application/src/agent/turn.rs`, `crates/adapter-http/src/routes/agent.rs`, `crates/adapter-http/src/routes/combat.rs`, `src/api/agent.ts`, `src/features/combat/model/commands.ts`, `src/state/chat.ts`, `src/styles/shell.css`, `src/components/ChatPanel.module.css`, `src-tauri/src/processes/`
**Severity:** high

## Problem

Long local-model turns emitted thousands of tiny SSE events. In WebView2 this amplified loopback connection pressure, reasoning token estimates appeared to reset between tool rounds, and the application document could grow vertically instead of keeping scrolling inside chat. Runtime process ownership also performed slow control work on the Tauri command path.

## Root Cause

Provider chunk boundaries were forwarded directly as application events, transport consumers waited beyond their application terminal event, and several empty HTTP responses were left unread. The reasoning token indicator was derived only from the currently visible reasoning fragment rather than a turn-level monotonic estimate. CSS grid and flex descendants lacked the `min-height: 0` containment required for a nested scroller. Runtime control mixed command dispatch and slow process work instead of using the dedicated executor.

## Solution

The application service now coalesces adjacent text and reasoning deltas while preserving event ordering. Agent and combat transports terminate and release their readers after the authoritative terminal payload, empty response bodies are explicitly discarded, and server SSE responses request connection closure. The chat slice maintains a monotonic turn-level reasoning estimate and resets it only when a new stream begins. Shell and chat containers now constrain height and overscroll. Tauri runtime control delegates slow lifecycle operations to its executor, with safe `[FIX:runtime-control-executor]` lifecycle logs.

## Prevention

- Test SSE consumers with fragmented input, EOF tails, terminal events, reader cancellation, and lock release.
- Characterize semantic event content rather than provider-specific chunk boundaries.
- Keep the application viewport fixed and assign scrolling to an explicit `min-height: 0` descendant.
- Run real Tauri checks through WebView2 CDP after deterministic browser acceptance; do not infer desktop health from browser mocks.
- Stop live Tauri processes before Rust builds on Windows to avoid locked sidecar binaries.
- Keep GPU/model tests separate from offline sidecar tests and report skipped hardware coverage explicitly.
